## 3. MVP 范围

### 包含

- post-trained 0.8B 纯文本生成；
- batch 1，后续增加 batch 2；
- prompt length 16/128/1024，后续增加 4K/32K；
- decode length 16/64；
- prefill 和 decode 分开测量；
- BF16 和 W8A8-linear 两种精度模式；
- scalar reference 作正确性基线；
- 目标顺序：AVX2 → AVX-512 → SVE256 → NVIDIA → AMD；
- Ascend adapter 保持 BF16 回归，不作为新后端优先级。

### 首期不包含

- W8A16、W4A16/INT4、FP8、W4A4 或其他第三种精度模式；
- INT8 KV cache；
- GDR recurrent state 量化；
- 视觉编码器和图像/视频输入（已确认不纳入当前 MVP）；
- MTP 加速、speculative decoding；
- MoE 系列；
- 9B/27B 整网权重加载；
- 分布式/多卡。

## 4. BF16 精度契约

- 模型权重和主要 activation 保持 BF16；
- reduction、RMSNorm、Softmax、GDR recurrence 等数值敏感操作使用 FP32 中间累加；
- 输出按模型 contract 转回 BF16；
- AVX2 缺少原生 BF16 dot 时允许转 FP32 计算；
- AVX-512 BF16、SVE BF16、GPU BF16 通过 capability 探测选择，不在公共语义中假定必然存在。

## 5. W8A8 精度契约

本项目的 W8A8 首期定义为 `W8A8-linear`，而非把模型每个中间张量都保存为 INT8：

| 项目 | 契约 |
|---|---|
| Weight | signed INT8，对称，zero-point=0 |
| Weight scale | per-output-channel，FP32 metadata |
| Activation | 进入 quantized linear 前动态 signed INT8 |
| Activation scale | per-token/per-row absmax，FP32 metadata |
| GEMM accumulator | INT32 |
| Epilogue | scale 融合并转回 BF16，必要时 FP32 |
| Packed format | 逻辑量化格式共享；目标 packing 进 artifact cache |

最终 W8A8-linear 目标覆盖：

- full-attention Q/K/V/O projections；
- Gated DeltaNet QKV/Z/B/A/out projections；
- FFN gate/up/down projections；
- LM head（单独验证 tied embedding 与 logits 精度）；
- depthwise Conv1D 先保留 BF16，若它成为明显瓶颈，仍只能增加 W8A8 实现，不新增精度种类。

在 W8A8 模式中继续保持 BF16/FP32 的部分：

- embedding lookup（首期）；
- RMSNorm/gated RMSNorm；
- SiLU/sigmoid/softplus/exp/rsqrt；
- Softmax、RoPE/MRoPE；
- attention QK/PV 激活间 matmul（首期）；
- KV cache；
- GDR recurrent state、conv state 和递推核心；
- residual stream。

因此模型报告必须同时给出“W8A8 Linear 覆盖率”和“整网 INT8 计算占比”，不得用 `W8A8` 名称暗示 Norm/Softmax/GDR state/KV 也已量化。

```

### Dense Linear/FFN

```

### Full Attention

```text
Q/K/V projection
Q/K normalization
RoPE/MRoPE
GQA repeat-KV
QK^T + scale + causal mask + softmax + PV
attention output gate
output projection
KV cache append/read

```

### Gated DeltaNet

```text

Q/K L2Norm
softplus + gate/decay
chunk GDR prefill
recurrent GDR decode
conv state/recurrent matrix state
gated RMSNorm
output projection
```

`QuantizedTensorDesc` 需记录 signedness/bits/axis/granularity/scale dtype/zero-point policy/logical layout。公共 IR 不保存 AVX/VNNI、SVE DotProd/I8MM、CUDA Tensor Core 或 AMD gfx 物理 packing。

## 8. 后端 W8A8 路线

| 后端 | 首期路线 |
|---|---|
| scalar reference | 明确 INT8 量化、INT32 累加与 scale epilogue，作整数 golden |
| AVX2 | widening/dot 组合 + INT32 累加；不假定 VNNI |
| AVX-512 | 能力允许时使用 VNNI；独立检查 BW/VL/VNNI/XCR0 |
| SVE256 | 先有 widening fallback；SVE2 DotProd/I8MM 仅在 HWCAP2 证实后使用 |
| NVIDIA | INT8 Tensor Core/DP 路线由 CUDA capability 选择 |
| AMD | 接入后以实际 `gfx`/wave/ROCm 能力选择，不预先硬编码 |

## 9. 交付阶段

资源驱动调整：RTX 5080 GamePC 关机期间，项目没有等待 CUDA，而是在本地与鲲鹏 920B ECS 推进 M0/M1。用户于 2026-09-09 确认 5080 已恢复并由 PyPTO-X 独占 GPU；GPU-only CUDA 工作无需 `gamepc` 锁，只有大量远端 CPU/host-memory 阶段才持锁。恢复探测确认 `libcuda.so.1` 可用但缺 CUDA Toolkit/PyTorch/Triton，因此先走 Driver API + PTX JIT，不擅自安装软件。ECS 继续用于 SVE256 原生正确性和汇编验收；因其为 2 vCPU KVM guest，当前不据此冻结性能门槛。ECS 无 PyTorch、Transformers、NumPy，M0/M1 验收保持标准库、无权重、离线可运行。

### M0：模型基线和算子闭包

- 固定 model revision、tokenizer、Transformers 和 generation config；
- 建立 PyTorch BF16 整网参考与逐层 capture；
- 建立 0.8B 真实形状和 9B/27B 合成 shape harness。

M0 分两段执行：先交付不依赖 PyTorch/Transformers 的固定 text config、operator/state manifest 和 shape harness；PyTorch BF16 capture 等到参考环境获授权安装后再完成。不得因缺少参考框架而伪造逐层数值结论。

第一段已于 2026-09-08 完成：固定配置、operator/state manifest、capability gap matrix 与 12 场景 shape harness 均已冻结；PyTorch BF16 capture 仍等待参考环境与权重执行授权，不计作本次 M0 第一段缺口。

### M1：BF16 公共原语与 scalar reference

- 完成第 6 节 primitive；
- 单算子与 PyTorch reference 差分；
- 连通 prefill、decode、KV 和 GDR state。

M1 按依赖拆分，禁止先写孤立 target kernel：

1. M1A 公共 scalar math：`cast/exp/rsqrt/sigmoid/silu/softplus/reduce_mean/broadcast/where`；
2. M1B shape/layout：`reshape/view/transpose/contiguous/slice/split/concat/gather/embedding`；
3. M1C 将已冻结语义接入 vector-common，并在当前资源窗口先完成 SVE256/920B 原生验收；AVX2/AVX-512 保持显式拒绝，等待后续 parity 阶段；
4. 之后才进入 RMSNorm、SwiGLU、Softmax、RoPE 等复合算子。

M1A/M1B/M1C1/M1C2a/M1C2b/M1D/M1E/M1F/M1G 已完成并集成。M1C2a 处理 reshape/view/transpose/contiguous/slice；M1C2b 处理多输出 split、concat、gather/embedding；M1D 组合 RMSNorm/L2Norm/SwiGLU/Softmax/RoPE/GQA/mask；M1E 闭包 Conv/state；M1F 闭包 rank-2/3/4 attention matmul 与函数式 KV cache；M1G 闭包 q/k/v/beta BF16、g/state FP32 的 GDR recurrent matrix state。M1G 独立验收为 `438 passed`，固定 16×128 非零 QEMU/SVE 与 920B native 均通过。AVX 与 GPU 同类扩展保持独立门禁，不因 SVE 路径通过而宣称支持。

M1 剩余闭包按依赖继续拆分：

5. M1F（已完成）：为 QKᵀ/PV 增加 batched/transpose matmul 语义，并以 `prior_k/prior_v → new_k/new_v` 的函数式多输出闭包 KV cache append/read；
6. M1G（已完成）：闭包 Gated DeltaNet 的 recurrent matrix state/update，覆盖 sequential chunk reference 与逐 token decode，并记录 FP32 累加和状态误差；
7. M1H：补齐 compare/iota/position 等位置与控制原语，连接无权重 24 层 text decoder graph；
8. M1H 完成后，把 M1A–M1H 的冻结语义回填到 AVX2/AVX-512，再进入实际 BF16 模型执行。当前 SVE 优先是 5080 关机且 920B 可用时的资源调度，不改变正式后端优先级。

### M2：BF16 实际模型

按 AVX2 → AVX-512 → SVE256 → NVIDIA → AMD 的顺序，每个后端先通过单层，再通过 24 层纯文本生成。

## 10. 正确性与报告

每个 backend/precision 必须报告：

- 单算子 FP32/BF16 参考误差；
- W8A8 qmatmul 与整数 golden 的一致性；
- 每层 hidden state 和 GDR recurrent state 误差；
- final logits cosine/绝对-相对误差；
- top-1/top-5 一致率与 greedy token 首次分叉位置；
- 小型固定语料 perplexity 变化；
- peak memory、编译时间、cache hit、prefill/decode 延迟；
- PyPTO-X 实际覆盖的层/算子/计算量比例。

BF16 和 W8A8 的正确性证据从第一个后端开始持续记录；但具体性能验收门槛已确认延后到首批可运行后端完成后，再依据实测数据冻结，不在没有实测时预设倍率或延迟数字。

## 11. 完成定义

BF16 模型 MVP 要求固定 revision 完成纯文本 greedy prefill + decode，text decoder 主要计算经 PyPTO-X，fallback 明确列表，且逐层/logits/token/GDR/KV state 报告完整。

W8A8 模型 MVP 要求所有线性层的量化覆盖/例外清单完整，rounding/saturation/scale/packing 可复现，报告 W8A8 Linear 覆盖率，并与同 backend BF16 比较质量、性能和显存。
